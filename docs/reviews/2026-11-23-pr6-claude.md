## Must fix (plan)

- [ ] **M1 New users get the Confirm signup email, not Magic Link.** For an address with no account, Supabase sends the *Confirm signup* template. The plan edits only the Magic Link template, so every first-time colleague (the whole pilot) would get a link, and link-scanning mail filters can use it up. Fix: add `supabase/templates/confirm_signup_code.html` with `{{ .Token }}` and install it in *both* templates. `verifyOtp({ type: "email" })` already accepts both. Pilot gate: a never-used address must receive a code.
- [ ] **M2 Code lifetime.** Supabase's default is 1 hour. Set *Email OTP expiration* to 600 s and say "gyldig i 10 minutter" in both templates.
- [ ] **M3 The rollback is wrong.** `emailLogin: false` only hides the form. Once Gmail SMTP is configured, anyone can call `signInWithOtp` against the public API with the publishable key and make the Gmail account send mail to any address (mail bombing, Gmail suspension). Fix the plan text in EMAIL_LOGIN.md step 7. The real controls are in Supabase: set *Rate limits → emails per hour* low (10–30) before entering the SMTP password. Kill switches, in order: (1) remove the custom SMTP so the default sender (team-only) is used again, (2) revoke the Gmail app password. Do **not** disable the Email provider as a rollback, because it locks out every existing email user.
